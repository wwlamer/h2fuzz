# h2fuzz: устройство и методика

## 1. Состав

| Файл | Назначение |
|---|---|
| `frames.py` | сборка кадров h2, минимальный HPACK-кодировщик, заготовки HTTP/1.x запросов, мутатор |
| `fuzzer.py` | драйвер: режимы, потоки, подсчёт падений по логу MPM |
| `lab/build.sh` | сборка стенда нужной версии, по умолчанию ASan |
| `lab/httpd.conf` | минимальный конфиг: core и mod_http2, h2c |

Зависимостей нет, только стандартная библиотека.

## 2. Мутации HTTP/1.x

За основу берётся один из восьми валидных запросов: GET, HEAD, POST с Content-Length, POST с chunked, OPTIONS, обход пути, Expect. Затем применяется от одной до двенадцати операций:

- инверсия бита и замена байта;
- вставка случайных байтов и удаление фрагмента;
- дублирование фрагмента;
- вставка длинной серии `A` до 8000 байт;
- вставка `\r\n`, `:`, пробела, `\x00`, одиночных `\r` и `\n`;
- подстановка граничных чисел: 2^31, 2^32-1, 2^63-1, отрицательные, 10^20;
- подстановка битого chunked-обрамления: `ffffffffffffffff\r\n`, `-1\r\n`, пустой чанк.

Запрос отправляется в один или несколько write, чтобы попасть в разные ветки разбора.

## 3. Мутации h2c

Сначала ставится валидная сессия: `PRI * HTTP/2.0`, SETTINGS с `INITIAL_WINDOW_SIZE` из набора 0, 1, 100, 65535, 2^31-1. Затем от одного до шести стримов, и для каждого:

- HPACK-блок с длинными и пустыми значениями, повторяющимися именами, нестандартными методами и путями до 2000 байт;
- разбиение блока по CONTINUATION в случайной точке;
- PADDED DATA с длиной padding 0..255 и случайным телом;
- WINDOW_UPDATE на 0, 1 и 2^31-1;
- RST_STREAM в случайной точке;
- PRIORITY и PUSH_PROMISE на клиентском стриме.

В конце добавляются случайные кадры всех двенадцати типов.

Кодировщик HPACK минимальный: индексированные статические поля `:method`, `:scheme`, `:path` и литералы с инкрементальной индексацией для `:authority` и остальных заголовков. Длина строки кодируется с префиксом 7 бит, индекс имени с префиксом 4 бита, поэтому длинные пути не ломают блок.

## 4. Стенд

```bash
sh lab/build.sh 2.4.69 8520
lab/install-2.4.69/bin/httpd -f lab/httpd-2.4.69.conf -k start
```

Скрипт собирает с `-fsanitize=address`, потому что ASan полезен для ошибок в обычной куче и в самом httpd. Конфиг содержит только core и mod_http2, `Protocols h2c http/1.1`, `LogLevel warn`.

Переменные окружения для ASan задаются при запуске, пример:

```bash
ASAN_OPTIONS=detect_leaks=0:log_path=/tmp/asan_:abort_on_error=0:halt_on_error=0 lab/install-2.4.69/bin/httpd -f lab/httpd-2.4.69.conf -k start
```

## 5. Детектор

Счёт идёт по строкам `AH00051` и `AH00052` в `error_log`, плюс проверяется, что pid воркера не менялся. Это единственный надёжный способ для класса ошибок внутри bucket-аллокатора APR.

Почему ASan недостаточно, проверено на практике: сборка 2.4.68 с ASan под известным триггером падала 24 раза, и при этом ни одного отчёта ASan не появилось. Узлы bucket-ов берутся из собственного freelist `apr_bucket_alloc`, а не из malloc, поэтому санитайзер кучи их не отслеживает, а падение происходит уже после порчи списка.

Для отладки такого класса:

```bash
CFLAGS="-DAPR_BUCKET_DEBUG" sh lab/build.sh 2.4.69 8520
```

Тогда в `buckets/apr_buckets_alloc.c` сработает `check_not_already_free` и даст стек с повторным освобождением.

## 6. Результаты

Прогон на 2.4.69, один поток, локальный стенд:

| Режим | Время | Итераций | Падений |
|---|---|---|---|
| http1 | 240 с | 25 828 | 0 |
| h2, случайные кадры | 240 с | 91 015 | 0 |
| h2, структурные мутации | 300 с | 89 304 | 0 |

Воркер не перезапускался. Покрытие подтверждается логом: в нём появляются `AH03081 h2_stream ... invalid transition` и `AH00036`, то есть запросы доходят до парсера и до стейт-машины стримов.

## 7. Ограничения

- Нет обратной связи по покрытию. Это чёрный ящик по TCP, поэтому глубина ограничена. Для серьёзной работы нужен in-process харнесс на libFuzzer по `ap_read_request` и по `c1_in_feed_brigade`.
- Только h2c. TLS и ALPN не покрыты.
- Ограниченное время прогона не даёт права говорить об отсутствии ошибок. Формулировка корректная: за указанное число итераций падений не найдено.
- Мутации случайны, воспроизводимость обеспечивается флагом `-s`, но привязка к конкретному входу не сохраняется. Для сохранения входа нужен отдельный лог байтов, его здесь нет.
